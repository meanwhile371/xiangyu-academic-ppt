# 原论文图、机制图与图像后端

## 先选证据，再选生成方式

为每张图回答：支撑哪一页的哪项论断，读者需要看什么，以及为什么用这张图。能用原论文图说明实证时，优先使用原图，尤其是经典架构、算法轨迹、主实验曲线和应用结果。

图源至少记录原论文标识、图号与面板、PDF页、提取方式、裁剪范围、放置页和质量说明。PDF页与论文印刷页可能不同，要写清口径。公开材料的可阅读性不等于素材可任意再发布，保留引用并按实际授权使用。

## 原图保真

- 按用户要求保持原色、比例、标签、坐标轴、图例、面板字母和统计含义。
- 用户要求原封不动时，不局部改写图中文字。可在图外增加解释、放大副图或来源标记。
- 允许裁剪时，优先裁到有意义的面板，不能裁掉轴、样本数、色条、误差定义、比例尺或解释所需图注。
- 不把多面板中的不同任务、时间点或阈值当作可直接排名的重复结果。
- 原表有点估计与区间不一致时保留原值，说明待核查，不自己修成看起来正确的数据。

## 教学生成图

适用：过程、机制、目标分解、拓扑、算法时序、对比结构、概念关系，以及用户需要的场景引入与封面。

先给生成器明确语义：节点、输入输出、箭头方向、先后顺序、变量和每块文字。公式从已核实稿件提供，不能让生成器自行发明推导。检查图是否真的表达所需关系，而不只判断美观。

原项目的理论图风格是全英文黑白，原论文图保留彩色，两者分开处理。现实生活像素风只适用于相应场景。新任务若改了风格，以新要求为准。

文字、公式、流程框和连线在需要编辑时优先使用原生对象。复杂场景图、论文原图可以作为有明确边界的图片；不能把整页正文烘成一张图后声称整页可编辑。

## 图像模型和凭证

历史对话曾要求 GPT Image 2 / 2.5。模型名称只是用户期望，实际后端是否支持需要检查，不能据此保证某个API必然可用。选择符合任务的已有图片可以节省成本，但要说明实际来源，不伪称本轮重新生图。

组合模式优先遵守 PPT Master 当前图像工具的参数和配置接口。需要指定兼容服务时，通过环境变量设置，避免修改上游文件。示例变量名以固定版本工具文档为准：

```text
IMAGE_BACKEND=openai
OPENAI_BASE_URL=<provider-api-base-url>
OPENAI_API_KEY=<set-locally-do-not-commit>
OPENAI_MODEL=<verified-image-model-id>
```

具体调用方式先查看：

```bash
python vendor/ppt-master/skills/ppt-master/scripts/image_gen.py --help
```

如果用户给出完整 `/images/edits` URL，先确认工具需要的是基础URL还是完整端点，不要盲目再拼路径。编辑请求需要合适的输入图和服务支持，不能把编辑与纯生成的请求体混用。

记录请求模型、服务返回的可用生产信息、提示词、参考图、实际输出路径和放置页。不要保存Authorization头、密钥或含敏感查询参数的URL。失败时记录失败，不能把旧图冒充新生成结果。

用户授权某个服务处理图片，不自动授权上传全部论文、整份私有报告或其他项目。只发送本次必要且已授权的素材。没有被允许的后端时，继续进行不依赖生图的内容与排版工作，必要时再提出具体缺口。
